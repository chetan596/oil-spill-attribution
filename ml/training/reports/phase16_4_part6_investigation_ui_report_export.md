## 1. UI Architecture

The `/analysis/:id` page has been restructured from a disconnected set of diagnostic viewers into a cohesive, production-grade intelligence suite: **OCEAN GUARD AI — INVESTIGATION WORKSPACE**.

### Component Hierarchy
```
Analysis.jsx
  ├── InvestigationWorkspace.jsx (Conditional on manualInvestigationData)
  │     ├── InvestigationHeader.jsx (Job identity, acquisition time, scene hash, SHA-256)
  │     ├── ProvenanceLegend.jsx (REAL, MODEL-DERIVED, DEMO, NOT AVAILABLE, TIME PROXY)
  │     ├── InvestigationExportControl.jsx (JSON, GeoJSON, Report, Manifest exports)
  │     ├── InvestigationSummaryPanel.jsx (Executive metrics, spill area, candidate count)
  │     ├── InvestigationInputModelCard.jsx (Sensor, dimensions, model card, weights hash)
  │     ├── InvestigationDetectionPanel.jsx (Visual evidence, masks, real artifacts only)
  │     ├── InvestigationGeospatialPanel.jsx (CRS, bounding box, spatial validation)
  │     ├── InvestigationOriginPanel.jsx (Estimated coordinates, uncertainty corridor, MetOcean demo warning)
  │     ├── InvestigationDriftPanel.jsx (Backtrack trajectory, forecast status, Lagrangian dynamics)
  │     ├── InvestigationAisPanel.jsx (Potential vessel candidates, radar cards, AIS demo warning)
  │     ├── InvestigationAttributionPanel.jsx (NOT_ESTABLISHED status, legal disclaimer)
  │     └── InvestigationLimitationsPanel.jsx (Auto-synthesized scientific caveats)
  └── AnalysisMap.jsx
        └── ManualMapLegend.jsx (7-layer contextual symbology)
```

### State Isolation & Switching
- When navigating to `/analysis/:jobId`, any prior investigation state is immediately purged.
- Stale analysis results or layer toggles cannot bleed between scenes or jobs.
- All workspace panels and export triggers bind exclusively to `activeJobId`.

## 2. Canonical Data Consumption

**Architectural Law**:
```
canonical investigation snapshot (Parts 1–5)
                     ↓
             UI / Multi-Format Exports
```
**Export services and UI components NEVER rerun:**
- ML inference or feature extraction
- Geometry extraction or polygonization
- Spill origin estimation
- Drift simulation or Lagrangian backtracking
- AIS spatiotemporal correlation or candidate scoring

All operations are strictly pure read-only transformations and serializations of the stored canonical investigation snapshot.

## 3. Provenance Presentation

The workspace enforces unambiguous semantic categorization across all visual widgets and exported data:

| Provenance Level | Visual Token / Badge | Meaning | Permitted Usages |
|---|---|---|---|
| **REAL** | Emerald badge (`#10b981`) | Verified physical or sensor telemetry | Georeferenced raster bounds, raw image dimensions, SHA-256 hash |
| **MODEL-DERIVED** | Cyan / Sky badge (`#06b6d4`) | Generated by ML / numerical models | Spill mask footprint, centroid, estimated origin, drift trajectory |
| **DEMO** | Amber badge (`#f59e0b`) | Bundled test / demonstration dataset | Simulated MetOcean hydrodynamic forcing, demo AIS tracking database |
| **NOT AVAILABLE** | Slate / Gray badge (`#64748b`) | Metric or artifact missing / uncomputed | Non-georeferenced imagery, absent forward drift forecast |
| **TIME PROXY** | Purple badge (`#a855f7`) | Inferred temporal timestamp | Detection time inferred from ingestion when raster metadata lacks tag |

*Rule: Under no circumstances is `MODEL-DERIVED` ever relabeled as `VERIFIED` or `CONFIRMED`.*

## 4. Map Integration & Symbology

`ManualMapLegend.jsx` overlays directly on the investigation map, providing visual reference for all 7 active layers:
1. **Scene Bounds**: Real image footprint polygon (CRS-verified bounding box).
2. **Spill Extent**: Model-derived polygon (`#ef4444`, 35% fill, 2px border).
3. **Spill Centroid**: Model-derived geometric center (red target dot with ring).
4. **Estimated Spill Origin**: Model-derived origin point (`#a855f7`, star marker) with radial uncertainty buffer.
5. **Backward Drift Trajectory**: Model-derived backtracking path (`#f97316`, dashed orange line with direction arrows).
6. **Forward Drift Trajectory**: Model-derived forward forecast (`#3b82f6`, dashed blue line) or marked `FORECAST NOT AVAILABLE`.
7. **Potential AIS Candidates**: Historical vessel tracks (`#10b981` or `#f59e0b` demo), with closest approach indicators.

## 5. Technical Report Generation (15 Sections)

`investigationExportService.exportReport()` generates a complete Markdown technical dossier adhering to the 15-section standard:

1. **Investigation Summary**: Job ID, timestamp, scene metadata, executive summary.
2. **Input & Acquisition**: Original filename, MIME type, dimensions, CRS, acquisition time source.
3. **AI Model & Inference**: Architecture (`DeepLabV3+` / `UNet`), checkpoint version, weights SHA-256.
4. **Spill Detection**: Binary detection flag, confidence, pixel area, severity rating.
5. **Geospatial Analysis**: Bounding box, affine geotransform, centroid coordinates, projection validity.
6. **Spill Footprint**: Surface area in km², polygon complexity, coordinate array summary.
7. **Estimated Spill Origin**: Backtracked origin coordinates, uncertainty radius, temporal estimation offset.
8. **Drift / Backtracking**: Simulation parameters (hours back, hours forward), Lagrangian drift dynamics.
9. **Environmental Data Provenance**: Forcing data source (explicit `DEMONSTRATION METOCEAN FORCING` banner when DEMO).
10. **AIS Correlation**: Search window, bounding radius, total correlated candidate vessels.
11. **Potential Vessel Candidates**: Detailed cards for each vessel (MMSI, IMO, name, flag, type, closest approach, evidence scores).
12. **Attribution Status**: Mandatory `NOT_ESTABLISHED` declaration. Explicit assertion: *"AIS correlation does not establish vessel responsibility."*
13. **Evidence Limitations**: Auto-synthesized list of technical caveats, sensor constraints, and simulation bounds.
14. **Provenance Summary**: Comprehensive tabular audit of all inputs, models, and intermediate data.
15. **Technical Metadata**: Deterministic investigation fingerprint, export timestamp, generator identity.

## 7. GeoJSON Export

- Route: `GET /api/v1/manual-analysis/:jobId/export/geojson`
- Content-Type: `application/geo+json`
- Feature Gating: Only features that genuinely exist are included. No empty geometry placeholders.
  - `ImageFootprint`: Included only if CRS and geotransform are valid.
  - `SpillFootprint`: Included only if segmentation polygon is present.
  - `SpillCentroid`: Included only if centroid coordinates exist.
  - `EstimatedOrigin`: Included only if origin status is `ESTIMATED`.
  - `BackwardDriftTrajectory`: Included only if backward coordinates array is non-empty.
  - `ForwardDriftTrajectory`: Included only if forward status is `ESTIMATED` (omitted if `NOT_AVAILABLE`).
  - `AisCandidateTrack`: Included for each candidate with recorded trajectory points.
- Feature Properties: Every feature explicitly embeds:
  ```json
  {
    "featureType": "EstimatedOrigin",
    "provenance": "MODEL_DERIVED",
    "source": "LAGRANGIAN_SIMULATION_BACKTRACK",
    "status": "ESTIMATED",
    "investigationId": "..."
  }
  ```

## 8. Artifact Manifest Export

- Route: `GET /api/v1/manual-analysis/:jobId/export/manifest`
- Content-Type: `application/json`
- Purpose: Secure, machine-readable audit catalog of all generated assets (input raster, segmentation mask, vector GeoJSON, technical report, canonical JSON).
- Security Gating:
  - Strict absence of server filesystem paths, Windows drive letters (`D:\...`), Unix absolute paths (`/tmp/...`), and temporary folder references.
  - Filesystem paths are sanitized to relative filenames via `sanitizePath()`.
  - No environment variables, secret keys, or internal credentials are exposed.
  - Each item includes `filename`, `mediaType`, `sha256`, `artifactType`, `provenance`, `source`, and `status`.

## 9. Artifact Handling & Gating

- The UI strictly gates artifact rendering: only genuine, non-empty artifacts with valid URLs or relative endpoints are presented.
- No fabricated download links or placeholder buttons are displayed for missing items.
- If segmentation mask or probability maps are absent, the panel displays `NOT AVAILABLE` instead of a broken image frame.

## 10. Attribution Guardrails

Strict architectural enforcement prevents premature or unscientific legal attribution:
1. **Attribution Status**: Invariably `NOT_ESTABLISHED`.
2. **Forbidden Vocabulary Enforcer**: `assertNoForbiddenAttribution()` scans every export payload and throws an exception if any of the following strings/keys appear:
   - `responsibleVessel`
   - `confirmedPolluter`
   - `definitiveSource`
   - `provenResponsibleVessel`
   - `CONFIRMED POLLUTER`
   - `RESPONSIBLE VESSEL`
   - `PROVEN SOURCE`
3. **Candidate Status**: Every vessel is explicitly tagged `POTENTIAL_CANDIDATE` and described as a *"spatiotemporal correlation"*.
4. **Mandatory Disclaimer**: Every report and UI screen bears the legal declaration:
   > *"AIS correlation indicates spatiotemporal proximity only and does NOT constitute evidence of discharge responsibility."*

## 11. Demonstration Data Handling

When live or verified operational feeds are unconfigured:
- MetOcean data is explicitly labeled:
  ```
  [DEMONSTRATION METOCEAN FORCING]
  Synthetic or historical hydrodynamic currents utilized for drift simulation. Not calibrated to live oceanographic conditions.
  ```
- AIS data is explicitly labeled:
  ```
  [DEMONSTRATION AIS DATA — NOT REAL-WORLD AIS EVIDENCE]
  Vessel telemetry sourced from bundled demonstration records. Spatial-temporal correlation does not indicate physical involvement.
  ```

## 15. Known Limitations

1. **Client-Side PDF Rendering**: The technical report export currently serves a structured GitHub-flavored Markdown dossier (`text/markdown`). Browser native print-to-PDF is supported via standard CSS print media queries; server-side headless Chromium PDF rasterization can be added in a future operational deployment.
2. **Synchronous Export**: For extremely large GeoTIFFs (>500 MB) or long AIS tracking histories (>50,000 points), GeoJSON serialization is executed synchronously in-memory. For production big-data scenarios, background worker streaming to object storage may be implemented.
3. **Demo AIS Window**: AIS correlation continues to rely on the bundled Arabian Sea test dataset unless external live AIS providers (e.g. Spire, MarineTraffic) are configured with API credentials.
